# [PROPOSAL] kuna FID (Function-ID Fingerprinting) — Implementation Plan

**One-line:** Port Ghidra's FID *mechanism* — FNV-1a64 operand-masked function fingerprinting + full-hash re-identification — end-to-end over kuna's Listing tier, gated behind a new default-off `--option fid`, real-ELF path only. The fingerprint **database is kuna's own format, generated by kuna from a static lib**; Ghidra `.fidb`/`.fidbf` interop is an explicit, documented non-goal in the initial scope (with a clear extension point left for it).

This synthesizes Draft A (minimal-DB) and Draft B (faithful-.fidb). **Draft A is the recommended spine; Draft B's faithfulness rigor is folded in where it costs little (byte-exact hash, exact schema model, Ghidra-validated golden vectors, the full seeker as a planned increment).** The one place the drafts genuinely disagree — *parse real `.fidb` or not* — is resolved below as the headline decision.

---

## 1. The crux: where the fingerprint database comes from

### Decision: **kuna-native generated DB (option B), seeded as a tiny vendored fixture. Ghidra `.fidb`/`.fidbf` parsing is DEFERRED to a documented, firewalled extension point — NOT in the initial scope.**

| Option | Verdict | Reasoning (verified) |
|---|---|---|
| **A — parse Ghidra `.fidb`/`.fidbf`** | **Deferred (post-v1, optional)** | `find ~/github/ghidra -name '*.fidb'` → **0 files**: the datasets are a *separate multi-GB Ghidra release extension*, **not in the source tree and not vendorable**. The format is Ghidra's generic `db` framework (`Ghidra/Framework/DB`, 119 Java files: BufferFile/BTree/MasterTable/Schema/ChainedBuffer) — `FidDB.java` opens it via `db.DBHandle`/`PackedDatabase`. Draft B argues a read-only `.fidbf` subset is ~2k LOC and validatable, and *it's right that this is the faithfulness payoff* — but it is **net-new storage-engine surface kuna owns forever, that `sync_upstream.py` does not track**, gated on host-supplied datasets the test cannot vendor. Wrong thing to block the first ship on. |
| **B — kuna fingerprints a static lib → kuna-native DB** | **CHOSEN** | The container has `gcc`/`clang`/`ar`/`nm` + `libc.a`; kuna already has the disassembly + (new) SLEIGH mask + reloc info (`elf_reloc.rs`) the hasher consumes. Produces a faithful DB in a trivial flat format. Zero external-format risk; hermetic, regenerable fixture. |
| **C — tiny hand-built/vendored DB** | **Chosen *form* of the fixture** | The committed test DB is *generated by B* (faithful) but *vendored as output* (hermetic — `make test` never shells out to `gcc`). |

**Net headline for the [PROPOSAL]:** *kuna ships the FID mechanism and its own `.fid` DB format, generated from a kuna-owned static library and vendored small. It does not ship or read Ghidra's datasets.* The schema and hash are nevertheless ported **exactly** (Draft B's discipline), so kuna's native DB is structurally a Ghidra FID DB — making a future `.fidbf` reader a *natural extension behind a `FidDb` trait*, not a rewrite. That extension is explicitly scoped out here and recorded as a follow-on (PR7+).

### LOSS to document (`docs/rust-port/losses.md`)
- **kuna ships the FID *mechanism*, not Ghidra's datasets.** The multi-GB FunctionID datasets (`.fidb`/`.fidbf` for VS runtimes, glibc variants) are a separate Ghidra release artifact, **not in the source tree, not vendored**; kuna will not redistribute them.
- **`.fidb`/`.fidbf` interop is deferred (not a v1 goal).** Reading them requires porting the ~120-file `Ghidra/Framework/DB` packed-DB/BTree/buffer-file engine — disproportionate to block on. kuna uses its **own `.fid` format**, generated by kuna. The `FidDb` trait leaves a clean seam to add a read-only `.fidbf` reader later (Draft B's PR6).
- **What kuna ports faithfully:** FNV-1a64 full/specific hashing (`MessageDigestFidHasher`, byte-exact, magic verbatim), the extent generator (`FunctionBodyFunctionExtentGenerator`), the x86 instruction skipper, the `FidHashQuad` record, the FID **schema model** (field-for-field), and full-hash exact-match identification with the trusted-name label gate.
- **The one place kuna is *less* faithful than Ghidra:** the function extent is reconstructed as the **address-contiguous `[entry, next_function_after(entry))` clip** (kuna's Listing tracks entries, not bodies — `listing/mod.rs:342-344`), not Ghidra's true flow-reachable body. Interleaved/outlined bodies are mis-clipped. This is the same approximation `s1_noreturn_disc` already accepts.
- **Deferred (TODO, not correctness loss):** the `FidProgramSeeker` relation-graph (parent/child) scoring, the `code_unit + 0.67*specific + child + parent` accumulation vs `SCORE_THRESHOLD=14.6`/`MULTINAME=30`, the specific-hash tiebreak mode, and the `auto_pass`/`auto_fail`/`force_specific`/`force_relation` flags. v1 *stores* the fields these need (`specific_hash`, `specific_addl`, `flags`) so the scorer drops in without a format bump.

## 3. The SLEIGH instruction-mask accessor (new kuna-sleigh code)

The decoder discards the matched `DisjointPattern` after `DecisionNode::resolve` (verified `slghsymbol.rs:1860` returns `u32` ct, not the pattern). There is **no** `instruction_mask` today (verified absent; siblings are `instruction_length` `:2022`, `print_assembly` `:2028`, `one_instruction` `:2047`). Two additions:

### 3a. `DecisionNode::resolve_matched` (`slghsymbol.rs`, beside `resolve` at `:1860`)
```rust
pub fn resolve_matched(&self, walker: &dyn SymbolWalker) -> KunaResult<&(DisjointPattern, u32)>
```
A variant of `resolve` that walks the decision tree identically but, at the terminal node, returns the matched **`(DisjointPattern, ct)` pair** instead of just the ct id. **Why a pair, not a ct lookup:** one constructor can sit under several `(DisjointPattern, ct)` leaves (different context/operand specializations) — we must capture the *specific* leaf that matched, by re-running `pat.is_match`, not look up "the pattern for this ct" (there isn't one). `DisjointPattern::get_mask` (`slghpattern.rs:848`) and the tree (`get_list`/`get_children`) are already `pub`; this is the one missing internal hook.

### 3b. `Sleigh::instruction_mask` (`sleigh.rs`, beside `instruction_length` at `:2022`)
```rust
/// Decode the instruction at `baseaddr`; return (raw bytes, fixed-bit mask, length[, operands]).
/// fixed_mask[i] has 1 wherever SLEIGH pins a fixed opcode/encoding bit; 0 = operand/variable.
/// FID's "full mask" = bytes[i] & fixed_mask[i];  operand_mask = !fixed_mask.
pub fn instruction_mask(&self, baseaddr: &Address) -> KunaResult<InsnMask>
```
Returning:
```rust
pub struct InsnMask {
    pub bytes: Vec<u8>,            // len = length
    pub fixed_mask: Vec<u8>,      // operand_mask = !fixed_mask
    pub length: i32,
    pub operands: Vec<OperandView>,  // per-operand value-bit range + classified op-objects
}
pub struct OperandView { pub value_mask: Vec<u8>, pub objects: Vec<OpObject> }
pub enum OpObject {
    Scalar { signed: i64, whole_operand: bool, is_address: bool },
    Register { offset: u64 },
    Address,
}
```

**Implementation (must live inside `sleigh.rs` — `obtain_context`/`ParserContext`/`ConstructState`/`ParserWalker` are private):**
1. `let pos = self.obtain_context(baseaddr, ParseState::Disassembly)?;` (`:1821`) → constructor tree + length; `let len = pos.get_length();`.
2. `let mut fixed = vec![0u8; len as usize];`.
3. Walk the matched `ConstructState` tree (`base_state` + `push_operand`/`pop_operand`, same shape as `resolve_handles` `:1749`). Per node:
   - get its `ConstructorRef` and byte `offset` (`ConstructState.offset`),
   - `let (dp, _ct) = node_subtable.resolve_matched(walker)?;` (3a),
   - OR its fixed bits into `fixed`, **shifted by the node's `offset`**, byte-by-byte: `fixed[offset + b] |= dp.get_mask((b*8) as i32, 8, /*context=*/false) as u8;`
   - collect the per-operand value masks (`get_operand_value_mask(ii)` analog from the operand handles) and classify op-objects into `OpObject`.
4. `let bytes = self.get_load_image().load(len, baseaddr)?;` (or copy `pos.buf[..len]`). Return `InsnMask { bytes, fixed_mask: fixed, length: len, operands }`.

**Gotchas honored (from the kuna-sleigh-mask map):**
- **Multi-word/variable-length masks:** `PatternBlock` is multi-`u32` with a byte `offset`; `get_mask(startbit,size)` yields ≤32 bits per call. Loop byte-by-byte across `get_length()` respecting each node's `offset` (sub-constructors sit at non-zero offsets) — the `is_instruction_match` offset loop (`slghpattern.rs:470`) is the reference.
- **Context stream is not byte position:** use only `context=false`. The context stream (ARM TMode, MIPS ISA mode, x86 opsize) steers *which* constructor matches but has no instruction-byte position; `get_mask(..,true)` returns context-register bits — never fold into the byte mask. The matched tree is already context-correct (`obtain_context` loaded context).
- **Delay slots:** separate `ParserContext`s appended after the main one (`:2064-2086`). A per-`addr` `instruction_mask` naturally fingerprints one instruction; the FID extent walker steps by `len`.
- **`MAX_INSTRUCTION_LEN=16`** (`sleigh.rs:63`) is the buffer/mask cap.
- **Ellipsis** is already resolved into concrete `PatternBlock` offsets at decode time — the leaf `DisjointPattern` is concrete; no special handling.

Effort: **M–L, two files.** Everything else (`get_mask`, the tree, the byte buffer, length) already exists. This is the accessor the build-plan flagged as the AIF/FID-family prerequisite.

## 4. The FidHash port (`s1_fid/hash.rs` + `extent.rs` + `skipper.rs`)

**Byte-exactness is non-negotiable** (Draft B's discipline): a one-bit divergence makes every hash miss silently. Port `MessageDigestFidHasher.hash` line-for-line; validate against Ghidra-emitted hashes (§7.1), not just self-consistency.

### 4.1 FNV-1a64 (`hash.rs`)
```rust
const FNV_64_OFFSET_BASIS: u64 = 0xcbf2_9ce4_8422_2325;
const FNV_64_PRIME: u64        = 1_099_511_628_211; // 0x100000001b3
pub struct Fnv1a64 { h: u64 }
impl Fnv1a64 {
    fn new() -> Self { Self { h: FNV_64_OFFSET_BASIS } }
    fn update_byte(&mut self, b: u8) { self.h ^= b as u64; self.h = self.h.wrapping_mul(FNV_64_PRIME); }
    fn update_bytes(&mut self, buf: &[u8]) { for &b in buf { self.update_byte(b); } }
    /// AbstractMessageDigest.update(int) — 4 bytes BIG-ENDIAN (>>24 first).
    fn update_i32(&mut self, v: i32) { let v = v as u32;
        self.update_byte((v>>24) as u8); self.update_byte((v>>16) as u8);
        self.update_byte((v>>8) as u8);  self.update_byte(v as u8); }
    fn digest_long(&mut self) -> u64 { let r = self.h; self.h = FNV_64_OFFSET_BASIS; r } // resets
}
```
**Load-bearing:** `wrapping_mul`/`wrapping_*` everywhere (Java `long`/`int` two's-complement overflow is observable); big-endian `update(int)` order verbatim; `digestLong` resets to basis.

### 4.2 The quad + hasher
```rust
pub struct FidHashQuad {
    pub code_unit_size: i16,    // count-after-skips minus calls (Ghidra short)
    pub full_hash: u64,
    pub specific_addl_size: u8, // min(specificCount, 127)
    pub specific_hash: u64,
}
```
`FidHasher::hash(insns: &[InsnMaskView]) -> Option<FidHashQuad>` reproduces `MessageDigestFidHasher.hash` **exactly**. Constants: `SHORT_HASH_CODE_UNIT_LENGTH=4`. Counters: `specific_count=0`, `call_count=0`, `code_unit_index=-1`. Reject up front if extent `< 4`.

Per instruction (extent = body instructions ascending; §4.3), `code_unit_index += 1` (break at `Short::MAX-1`):
1. Read `len` bytes at `addr` into a buffer (re-read via loadimage — `Insn` has **no `bytes` field**, verified `model.rs:23-35`).
2. **Skipper:** for each registered `InstructionSkipper` (x86 only initially), if `should_skip(buf,len)` → `code_unit_index -= 1; continue`. (Non-x86: empty set → never skips.)
3. If `insn.flow.is_call()` (verified `Insn.flow` `model.rs:31`) → `call_count += 1`.
4. **Operand sub-hashing** — per operand `ii`: `let (mut full_u, mut spec_u): (i32,i32) = ((ii as i32 + 1)*7777, (ii as i32 + 1)*7777);`. For each `OpObject` (from §3's `InsnMask.operands`):
   - **Scalar** (`val = signed`): apply the **4-way rule in order** →
     1. `has_relocation(value_mask byte range)` → placeholder (relocation independence; reloc source `elf_reloc.rs`),
     2. else `whole_operand && is_address` → placeholder,
     3. else `!whole_operand && (val >= 256 || val <= -256)` → placeholder,
     4. else **small/usable**: `specific_count += 1`, keep the real value.
     Mix (wrapping i32): `spec_u = spec_u.wrapping_add(if kept { (val as i32).wrapping_add(1234567).wrapping_mul(67999) } else { (0xfeeddeadu32 as i32).wrapping_add(1234567).wrapping_mul(67999) }); full_u = full_u.wrapping_add(0xfeeddeadu32 as i32);`
     **The full hash NEVER sees a scalar value — only the `0xfeeddead` placeholder** (the position/relocation-independence guarantee). The `(int)` truncation of the 64-bit `val` before mixing is observable — reproduce it.
   - **Register** (`off = offset`): `let m = (off as i32).wrapping_add(7654321).wrapping_mul(98777);` add to **both** `full_u` and `spec_u` (registers are structural, always hashed).
   - **Address object:** treated as a rejected scalar (placeholder into both).
   - After the operand: `full.update_i32(full_u); spec.update_i32(spec_u);`
5. **Mask opcode bytes:** `for i in 0..len { buf[i] &= fixed_mask[i]; }` (every operand bit ANDed to 0). On no-usable-mask (Ghidra NPE analog — `instruction_mask` error) → fill `buf[..len]` with `0xa5`.
6. **Feed masked bytes to BOTH digests:** `full.update_bytes(&buf[..len]); spec.update_bytes(&buf[..len]);`

After the loop: `code_unit_index += 1`. If `< 4` → `None`. Else `code_unit_size = (code_unit_index - call_count) as i16`, `specific_addl_size = min(specific_count,127) as u8`, `full_hash = full.digest_long()`, `specific_hash = spec.digest_long()`.

**THE critical fidelity invariant:** both digests run the **same instruction stream in the same order**; the only per-operand difference is `full_u` vs `spec_u`; and the masked-byte `update_bytes` is interleaved **after** all of that instruction's operand `update_i32` writes — re-check line order against `MessageDigestFidHasher.java` during implementation. Get the interleave wrong and FNV diverges even with identical inputs. **Magic copied verbatim:** `0xfeeddead`, `7777`, `1234567`, `67999`, `7654321`, `98777`, `0xa5`, `4`, `127`.

This module is ~250 lines, pure, unit-testable independent of the Listing.

### 4.3 Extent (`extent.rs`)
The Listing tracks entries, not bodies (`listing/mod.rs:342-344`). Reconstruct `[entry, next_function_after(entry))` over the flat `instructions()` map — the verified `s1_noreturn_disc` idiom:
```rust
let next = listing.next_function_after(entry).map(|f| f.entry);  // mod.rs:347
for (&vma, insn) in listing.instructions() {                     // mod.rs:207, ascending
    if vma < entry { continue; }
    if matches!(next, Some(n) if vma >= n) { break; }
    extent.push((vma, insn));
}
```
Documented loss: address-contiguous, not flow-reachable (§1 LOSS).

## 5. Database format + source (`s1_fid/db.rs`)

Deliberately **not** Ghidra's `db`. A flat, fixed-record file, full-hash-indexed in memory, modeled field-for-field on the FID `FunctionsTable`+`StringsTable` (so a future `.fidbf` reader/writer is a serialization swap behind the `FidDb` trait, not a model change).

### 5.1 On-disk `.fid` (kuna-native, version-stamped)
```
magic        "KFID"                      # 4 bytes
version      u32 (=1)                     # bump on ANY hash/skipper change (Ghidra VERSION=6 analog)
lang_id      len-prefixed UTF-8           # SLEIGH language id; MUST match the program's
cspec_id     len-prefixed UTF-8
n_records    u32
records[n]:  full_hash:u64 | specific_hash:u64 | code_unit_size:i16 |
             specific_addl:u8 | flags:u8  # bit0 HAS_TERMINATOR (rest reserved: auto_pass/fail/force_*)
             | name_off:u32              # offset into the string blob
string_blob  (interned, NUL-separated)
```
Loaded into:
```rust
pub struct FidDb { lang_id: String, cspec_id: String,
                   by_full_hash: HashMap<u64, Vec<FidRecord>>,  // the FULL_HASH_COL index
                   names: Vec<u8> }
```
`find_by_full_hash(h) -> &[FidRecord]` is the analyzer's only hot-path query (matches Ghidra — the analyzer queries by full hash only; specific hash is a stored tiebreak field, not an index). **Relations and the full library model are omitted in v1** (PR5 deferred) — but the v1 records carry `specific_hash`/`specific_addl`/`flags` so the scorer drops in without a format bump.

### 5.2 Generation (kuna's `FidServiceLibraryIngest` analog)
A `kuna fid build <lib.a|*.o> -o lib.fid --lang <id> --cspec <id>` subcommand (or, minimally, a `cargo test`-gated generator):
1. Parse the `.a`/`.o`, disassemble each member's functions via the real-ELF Listing path.
2. For each function with a real (non-default) symbol name and ≥4 code units: `FidHasher::hash` → quad. Skip thunks/externals/`null` hash (faithful to `hashAllTheFunctions`).
3. Intern names, dedup identical `(full,specific,name)` rows, write the `.fid`.

For the **committed fixture**, run this once by hand against `tests/fixtures/fid/lib.c -O2` and **vendor the resulting `lib.fid`** (tiny — a handful of records) so `make test` is hermetic. The fixture README/Makefile records the exact `gcc`/`ar` invocation so it's regenerable when `version` bumps.

## 6. The matching pass (`s1_fid/mod.rs`) — gated, default-off, never-fail

`FidPass` — default-OFF Listing consumer, structurally cloned from `NoReturnDiscoveredPass`:
```rust
#[derive(Default)] pub struct FidPass;
impl AnalysisPass for FidPass {
    fn stage(&self) -> Stage { Stage::S1 }
    fn id(&self) -> &'static str { "fid" }
    fn run(&self, ctx: &AnalysisCtx) -> AnalysisOutput {
        let mut out = AnalysisOutput::default();
        let Some(listing) = ctx.listing else { return out; };  // inert without the Listing
        let Some(db) = load_fid_db_for(ctx) else { return out; }; // inert without a DB
        for (&entry, _f) in listing.functions() {              // mod.rs:357, address-ordered
            let extent = build_extent(listing, entry);          // §4.3
            let Some(quad) = hash_extent(ctx, &extent) else { continue; };  // §4
            let recs = db.find_by_full_hash(quad.full_hash);    // §5.1
            if let Some(name) = pick_unique_name(recs, &quad) { // §6.1
                out.fid_names.push(FidMatch { addr: entry, name });
            }
        }
        out
    }
}
```
`hash_extent` calls the new `Sleigh::instruction_mask(addr)` (§3) per instruction; bytes re-read from the loadimage (not retained on `Insn`); `insn.flow.is_call()` supplies the call count.

### 6.1 v1 scope: exact full-hash match → unique name (`pick_unique_name`)
If the full-hash bucket has exactly one record (or all records collapse to one name after underscore-strip dedupe), return that name; ties / genuine multi-name → emit nothing (**conservative — never guess**). This is the minimal faithful subset the fixture needs.

### 6.2 Commit seam — the one net-new piece of plumbing
FID **renames** an already-installed `sub_<addr>`/`FUN_*` function. The commit SymFact path is an **idempotent add** (verified `commit_analysis_output` step-1 at `engine.rs:809-814`: `if find_function(...).is_none() { add_function }`), so a `SymFact` would no-op on an existing function. FID therefore needs:
1. **New fact + field** (`pass.rs`): `pub struct FidMatch { pub addr: u64, pub name: String }`; `AnalysisOutput.fid_names: Vec<FidMatch>`; **add `self.fid_names.extend(other.fid_names);` to `merge`** (verified `merge` at `pass.rs:276-288` does not yet handle it).
2. **New commit arm** (`engine.rs::commit_analysis_output`, after the no-return arm at `:920`): resolve the function by **address** with the no-return arm's resolver (`find_function_across_scopes`, verified `:909`), then **rename** via `Database::rename_symbol(sid, &m.name)` (verified `database.rs:3741`) + `prog.register_symbol(&m.name, addr)` (verified `engine.rs:200`):
```rust
for m in &out.fid_names {
    let addr = Address::new(Rc::clone(code_space), m.addr);
    if let Some((sid, _)) = prog.arch().symboltab.find_function_across_scopes(&addr) {
        if is_generic_placeholder_name(prog, sid) {        // the label gate, below
            prog.arch_mut().symboltab.rename_symbol(sid, &m.name)?;
            prog.register_symbol(&m.name, addr);
        }
    }
}
```
3. **Label gate** — `is_generic_placeholder_name` is kuna's analog of Ghidra's `!alwaysApplyFidLabels && hasUserOrImportedSymbols` gate: FID only overwrites the engine's own `sub_<addr>`/`FUN_*` placeholder, never a real `.symtab`/DWARF name. On a stripped binary every function is a placeholder → FID fires; on a named binary it defers. Exactly the right, demonstrable behavior.
4. **Gate** — `"fid" => arch.analysis_fid` in `analysis_pass_enabled` (§2.4).

### 6.3 Deferred to PR5 (the faithful seeker, `seeker.rs`)
The real `FidProgramSeeker`: family build (children via `refs_from` filtered `RefKind::Call` `mod.rs:307`; parents via `refs_to` `:301`, keyed by full hash), `scoreMatch` (`functionCodeUnits + 0.67*specificCodeUnits + childScore + parentScore` vs `SCORE_THRESHOLD=14.6`; specific-hash mode on `specific_hash` equality; `auto_pass`→raise to `MEDIUM=24`; `auto_fail`/`force_specific`/`force_relation` flags), sibling cull (keep top + ties at max overall), `MULTINAME=30` multi-name gate, and underscore-strip/demangle name collapse. v1 stores the needed fields; this is additive.

## 7. The testcase — stripped-binary re-identification

The one capability unique to FID: **re-name a function in a STRIPPED binary by matching it to a known library.**

### 7.1 Hash-fidelity gate (the critical one — Draft B's contribution)
Vendor a tiny set of **Ghidra-computed `(function → FidHashQuad)` golden vectors** for a known `.o` (dumped via a Ghidra/FID script over `tests/fixtures/fid/lib.o`), into `tests/golden/`. A `kuna-analysis` unit test disassembles the same `.o`, runs `FidHasher`, and asserts `full_hash`/`specific_hash`/`code_unit_size`/`specific_addl_size` match **byte-for-byte**. This is the only thing that proves the port is faithful rather than self-consistent. (If a Ghidra dump is impractical at implementation time, fall back to hand-computed quads on a 4-instruction sequence + self-consistency across two builds — but the Ghidra-validated gate is the target.)

### 7.2 End-to-end re-identification gate
**`tests/fixtures/fid/lib.c`** — distinctive, self-contained functions, each ≥4 code units, no external libc calls (so the body is fully self-contained and the hash is stable across link):
```c
unsigned kuna_crc32(const unsigned char *p, unsigned n){ unsigned c=~0u; while(n--){ c^=*p++;
    for(int k=0;k<8;k++) c=(c>>1)^(0xEDB88320u&-(c&1)); } return ~c; }
unsigned long kuna_strlen(const char *s){ const char *p=s; while(*p) p++; return p-s; }
void *kuna_memset(void *d,int v,unsigned long n){ unsigned char *p=d; while(n--) *p++=(unsigned char)v; return d; }
```
`kuna_crc32` is the star: a distinctive loop with the magic `0xEDB88320` immediate (exercises the specific-hash path), near-zero collision risk.

**Build (recorded in the fixture README/Makefile; vendored output committed):**
```
gcc -O2 -ffreestanding -fno-stack-protector -c lib.c -o lib.o
kuna fid build lib.o -o lib.fid --lang x86:LE:64:default --cspec gcc   # DB from UNSTRIPPED objects
gcc -O2 -c lib.c main.c && gcc lib.o main.o -o prog -static -no-pie && strip --strip-all prog
```
`main.c` calls each `kuna_*` (retention); `-static -no-pie` (stable addresses); `strip --strip-all` (symbol table gone). Both `lib.fid` (tiny) and `prog` are **vendored** so the test is hermetic.

**The two-state assertion** (a `kuna-analysis` integration test / `tests/stages/` case on the real-ELF path):
1. **Negative control / baseline:** load `prog` with `--option fid off`. The stripped binary's function that *is* `kuna_crc32` is generic — assert it's named `FUN_<addr>`/`sub_<addr>` (proves the name isn't coming from a leftover symbol, and that FID's value is visible).
2. **FID on:** load `prog` with `--option listing on --option fid on`, point FID at `tests/fixtures/fid/lib.fid`. Assert the same function is now **`kuna_crc32`** — recovered purely by full-hash match.

That `FUN_*` → `kuna_crc32` only-when-FID-on transition is the clean, end-to-end, *only-FID-could-do-this* proof. It runs **only on the real-ELF path** (loads an actual ELF), so the XML datatest **675/158 oracles never reach it**.

**DB-path wiring (v1):** read the DB path from a `--option`-adjacent env var / fixed fixture path resolved in the test (mirroring how `i386_pie_plt` reads `kuna_i386_pie_plt`), keeping the DB source out of the per-decompilation option surface for now; promote to a real `--fidb <path>` flag in PR7+.

## 9. Risks, scope & parity safety

- **Parity safety (primary):** FID is a Listing consumer; the Listing is built **only** on the real-ELF bootstrap (`commit_pending_analysis`, gated on `analysis_listing`), and **`--option fid` defaults off** with an explicit `analysis_pass_enabled` arm. The XML datatest path never builds a Listing → the **675/158 oracles are byte-identical at every PR**. Same isolation `s1_noreturn_disc` already relies on. *Verify:* every PR runs all three gates + `kuna catalog --check`.
- **Database coverage (the headline limitation):** kuna ships the *mechanism* + its own DB format, **not Ghidra's datasets**. Out of the box FID only re-identifies functions present in a kuna-generated `.fid` (the fixture lib, or a user's own `kuna fid build` output). Real-world glibc/VS coverage needs either user-built DBs or the deferred `.fidbf` reader (PR6+). Documented as LOSS (§1).
- **Faithfulness gap (extent):** address-contiguous `[entry,next)` clip, not flow-reachable bodies — interleaved/outlined code mis-clipped. The one place kuna is *less* faithful than Ghidra. Documented (§1).
- **Hash fidelity (silent-failure risk):** a one-bit divergence makes every hash miss with no crash. Mitigated by the **Ghidra-validated golden gate** (§7.1) and verbatim magic constants — this is why PR2 ships the golden test, not just self-consistency.
- **False-positive control:** v1 is conservative — exact full-hash match, emit a name only when the bucket collapses to **one** name, never guess on ties; and the **label gate** only ever overwrites a `FUN_*`/`sub_*` placeholder, never a real symbol. PR5 adds the full `0.67*specific + child + parent ≥ 14.6` / `MULTINAME=30` scoring + sibling cull for higher-recall, still-bounded matching.
- **Perf (hashing every function):** FID hashes every Listing-discovered function once when `--option fid on` — a per-function single decode-pass + FNV stream, on a path that's already opt-in and real-ELF-only. No hot-path impact on the default pipeline (FID never runs by default). Cache the per-function hash (Ghidra's MRU) if PR5's family build re-hashes neighbors.
- **`kuna-sleigh` blast radius:** PR1 is the only change to the proven decompiler core. It is purely *additive* (a new accessor + a new `DecisionNode` method) with no change to existing decode paths → zero behavior change; `make rust-test`'s `.sla` parity + datatest parity are untouched. Land PR1 first and independently.
- **Explicitly deferred (TODO, not correctness loss):** `.fidb`/`.fidbf` interop (PR6+), the packed-`.fidb` gunzip wrapper, any FID *writer* of Ghidra format, the demangler-based name collapsing, multi-architecture DB auto-generation, and the relation-graph scoring/flags (PR5).

**Bottom line:** the FID database does **not** come from Ghidra's `.fidb` (absent from source, disproportionate binary-format port deferred to an optional follow-on). It comes from **kuna fingerprinting a small kuna-owned static lib at build/test time, stored in a trivial kuna `.fid` format**, vendored tiny. The convincing testcase is a **stripped statically-linked ELF where `--option fid on` renames `FUN_<addr>` → `kuna_crc32` by full-hash match** — the one capability unique to FID — gated entirely to the real-ELF path so every parity oracle stays byte-identical. The hash and schema are nevertheless ported *exactly*, so the eventual `.fidbf` reader is a clean extension behind the `FidDb` trait, not a rewrite.
