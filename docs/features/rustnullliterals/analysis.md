# Rust null expressions

A pointer-typed zero was constructed as `core::ptr::null_mut()` and then sent through recovered-name sanitization, replacing its parentheses with underscores. The emitted `core::ptr::null_mut__` is not a defined item and fails to compile with E0425. The public C reproduction in `public-repro/` demonstrates that failure on the parent and compiles and returns null on the candidate.

The internal `LiteralToken` explicitly represents an already constructed expression. `PrintC::emit_atom` sends it through the ordinary variable-markup emitter, retaining the original operation and varnode associations without changing the expression's spelling. Only the Rust null-constructor site uses the new tag. The tag is appended to the enum so existing discriminants retain their values. Ordinary variables and enum constants still use identifier sanitization, including when highlighted as constants. C and Go keep their original null-token path. This corrects invalid Rust syntax; it adds no output preference or recovery heuristic and needs no option.

Three engine tests verify literal spelling under both highlights, continued character sanitization for recovered names, and identical operation/varnode provenance. Four authored native Rust functions cover null returns, selection of an existing pointer, null comparison and a store through a pointer-to-pointer. All four complete emitted bodies compile at O0/O2 and preserve 150 checked values over 15 boundary inputs. The harness tests pointer identity and null values within each process. The parent fails E0425. Complete C and Go function records are identical, and the only Rust-record difference is the constructor spelling; emitted bodies are never repaired by the harness.

The full comparison covers 46 images, 34,280 distinct functions and 77,556 language records. Exactly 3,084 Rust records change, fixing 22,066 constructor occurrences. Every changed whole record equals its parent with only `core::ptr::null_mut__` replaced by `core::ptr::null_mut()` in its code. Every other Rust field and record and every C and Go record is identical. The 15 inherited Go parser failures remain unchanged. This is a spelling correction, not a claim that all recovered upstream bodies compile or reproduce native behavior.

Validation passes 675 original assertions, 3682 stage assertions and 10,304 workspace tests, with 39 ignored and no failures. The original baseline is unchanged. Tooling, lint, the live spec, catalog and shared counters pass. An initial test incorrectly assumed the existing identifier sanitizer escaped reserved Rust keywords. Its failed log and a separate authored compiler counterexample are retained under `checks/` and `keyword-followup/`; that existing gap is not hidden or fixed in this change. The corrected control verifies the actual character-sanitization contract.

The current integration study uses seven cases, 384 balanced paired rounds per case, disjoint physical CPU pairs and one final look. Typed assertions select the pointer contracts in all four native cases. The study fails its predeclared bound for maybe_pointer, clear_pointer. No passed speed study is claimed; every observation is retained and the unchanged implementation was not repeated. Maximum median CPU and wall deltas are 0.366% and 0.300%; simultaneous upper bounds reach 1.141% CPU and 6.553% wall. Source, binary and all 154 compiled processor-specification hashes are checked before and after sampling. These results apply to the recorded cases and binaries.

Main c1745 added a P4 return-recovery call and changed its shared pair-retention helper while this fix was awaiting publication. The fix was integrated without changing its null-expression logic; a fresh independent parent and candidate were built, both sides of the full comparison were recaptured, and the two new MIPS fixtures were added as controls. All checks and native proofs were rerun. The initial study on 44eaff remains under `initial-44eaff/`: its null-return and null-store wall bounds were 5.130% and 5.081%, exceeding 5%, while every median change was below 1.1%. That failed study is retained regardless of the current integration result; no overall passed speed study is claimed. The integration plan was declared before collecting any new samples.
