# Rust null expressions

A pointer-typed zero was constructed as `core::ptr::null_mut()` and then sent through recovered-name sanitization, replacing its parentheses with underscores. The emitted `core::ptr::null_mut__` is not a defined item and fails to compile with E0425. The public C reproduction in `public-repro/` demonstrates that failure on the parent and compiles and returns null on the candidate.

The internal `LiteralToken` explicitly represents an already constructed expression. `PrintC::emit_atom` sends it through the ordinary variable-markup emitter, retaining the original operation and varnode associations without changing the expression's spelling. Only the Rust null-constructor site uses the new tag. The tag is appended to the enum so existing discriminants retain their values. Ordinary variables and enum constants still use identifier sanitization, including when highlighted as constants. C and Go keep their original null-token path. This corrects invalid Rust syntax; it adds no output preference or recovery heuristic and needs no option.

Three engine tests verify literal spelling under both highlights, continued character sanitization for recovered names, and identical operation/varnode provenance. Four authored native Rust functions cover null returns, selection of an existing pointer, null comparison and a store through a pointer-to-pointer. All four complete emitted bodies compile at O0/O2 and preserve 150 checked values over 15 boundary inputs. The harness tests pointer identity and null values within each process. The parent fails E0425. Complete C and Go function records are identical, and the only Rust-record difference is the constructor spelling; emitted bodies are never repaired by the harness.

The full comparison covers 59 images, 34,362 distinct functions and 77,802 language records. Exactly 3,084 Rust records change, fixing 22,066 constructor occurrences. Every changed whole record equals its parent with only `core::ptr::null_mut__` replaced by `core::ptr::null_mut()` in its code. Every other Rust field and record and every C and Go record is identical. The 15 inherited Go parser failures remain unchanged. This is a spelling correction, not a claim that all recovered upstream bodies compile or reproduce native behavior.

Validation passes 675 original assertions, 3699 stage assertions and 10,329 workspace tests, with 39 ignored and no failures. The original baseline is unchanged. The inherited stage footer overstated its 3,694 passing keys by three; the fresh 3,699-key baseline adds exactly five assertions and removes none. The failed preparation-count assumption and exact recovery comparison are retained. Tooling, lint, the live spec, catalog and shared counters pass. An initial test incorrectly assumed the existing identifier sanitizer escaped reserved Rust keywords. Its failed log and a separate authored compiler counterexample are retained under `checks/` and `keyword-followup/`; that existing gap is not hidden or fixed in this change. The corrected control verifies the actual character-sanitization contract.

An intermediate ed740 tree passed every gate, its complete 56-image review and 150 native values. It was superseded by the big-endian relocation change before any timing samples. Its proof is retained under `intermediate-ed740/`, including the initial missing-target invocations for two MIPS64 controls and their correction. The current 59-image comparison recaptures both sides independently with the required targets.

The current integration study uses seven cases, 384 balanced paired rounds per case, disjoint physical CPU pairs and one final look. Typed assertions select the pointer contracts in all four native cases. Every simultaneous CPU and wall bound passes the 5% budget. Maximum median CPU and wall deltas are 0.114% and 0.113%; simultaneous upper bounds reach 0.420% CPU and 1.685% wall. Source, binary and all 154 compiled processor-specification hashes are checked before and after sampling. These results apply to the recorded cases and binaries.

The two earlier studies remain under `prior-c1745/`. On 44eaff, the null-return and null-store wall bounds were 5.130% and 5.081%. On c1745, the selection and null-store wall bounds were 5.636% and 6.553%; maximum median CPU and wall changes were 0.366% and 0.300%. Both studies failed their predeclared bounds. Neither was repeated on unchanged code, and no overall passed speed study is claimed.

The current parent 8db14 integrates import-stub no-return analysis, sized-symbol function-discovery limits, MIPS GOT constants and unaligned lifting, including a new option, shared stage counts and big-endian ET_REL rebasing. The null-expression implementation is unchanged. Fresh independent parent and candidate binaries were built; both sides of the complete comparison were recaptured, with thirteen additional MIPS and big-endian relocation images. All gates and native proofs were rerun. The new measurement plan was declared before sampling. This revision has 373 catalog options and 678 corpus files.
