## The problem

A Win32 API whose arguments are staged across an intervening call loses the
staged ones. MSVC pushes `FormatMessageA`'s arguments 7..4, calls the
argument-less `GetLastError` in the middle of the run, then pushes 3..1 — and
kuna emits the outer call with three of its seven arguments and no trace of the
buffer whose address was among them.

```
$ kuna decompile calleeprotostack_pe_i386.exe 0x401000 --addr
void sub_401000(void)
{
  FormatMessageA(0x1300,0,GetLastError());
  ExitProcess(0); // no-return
}
```

With the fix it reads `FormatMessageA(0x1300,0,GetLastError(),0,&Stackfffffffc,0,0)`
— all seven values right, the buffer still carrying its raw stack name.

The fixture is `decompiler/crates/kuna-analysis/tests/fixtures/calleeprotostack_pe_i386.exe`
(generated by the `.py` beside it); its entry is the push sequence byte for
byte. `cstool x32 51 6a00 8d442404 6a00 50 6a00 ff1500204000 50 6a00 68 00130000 ff1504204000`
shows the four pushes in front of the `GetLastError` call and the three after it.

## The fix

`option calleeprotostack on|off`, default on, in `p4_calls/kuna_calleeprotostack.rs`.

- A locked parameter list under a model whose `<prototype extrapop="unknown">`
  declines to state its own cleanup implies `4 + <stack argument bytes>`.
  `FuncProto::resolve_extra_pop` computes exactly that and nothing in the tree
  called it, so a signed import still reached `StackSolver` as extrapop-unknown
  and `calleepop` guessed its cleanup off the push run in front of the call —
  crediting the four staged pushes to the wrong callee and latching a stack
  pointer 16 bytes too high into every later reference. A model that states its
  own extrapop already has the exact answer and is left alone, which keeps
  `__cdecl`, x86-64 and every RISC spec inert.
- `Heritage::guardCalls` gets `unknown_effect` for the whole stack and plants an
  INDIRECT over each of the caller's slots. Honest for an unknown callee; for a
  locked non-variadic one, the callee owns the return-address slot and its own
  parameter area and nothing above them, so a range wholly above that floor is
  left unguarded and the staged value reaches the call it was staged for.
- The second half is declined for any range a pointer in the caller could
  reach, via `AliasChecker::has_local_alias` — the test
  `FuncCallSpecs::checkInputTrialUse` already applies before it will call a
  stack slot a parameter. That is what keeps `ReadFile(h,&buf,…)` correct: the
  callee writes `buf` through the pointer, the guard models that write, and it
  stays. The gather is deferred and cached for one heritage pass.

## The tests

`tests/cli/getlasterror-consumes-arguments-prepared.json` is the promoted
acceptance probe: seven arguments, `GetLastError()` argumentless, an address-of
among the arguments, and no invented incoming parameter. It fails with
`--option calleeprotostack off`. Unit tests for the offset arithmetic and the
decline conditions live in the module. No `tests/stages/` case: the datatest
harness cannot `load file` a synthesized PE (the existing `win32sigs_pe_i386.exe`
fails there too), so the corpus cannot express an import-driven fixture.

Gates: `make test` 675/675 PARITY OK, `make test-stages` 704/704 PARITY OK,
`make test-cli` 100/100, `make check-spec` OK, `make rust-test` green,
`kuna catalog --check` OK. The default-on flip moves 0 of 675 datatest
assertions — both parity corpora are symbol-less byte chunks whose callees carry
no declared prototype, so nothing in them reaches the locked branch.
