# High-byte jump-table guards

`--option highsliceguard on` recovers a table whose index is a logical right shift and whose bound compares the equivalent complete high-byte slice. The option is off in every preset because recovering the upstream table exceeded the default speed budget. The standalone assembly reproduction in `public-repro/` retains its indirect call by default and recovers all 41 cases when enabled.

`kuna_highslice_guard::matches` proves an exact identity. Both operations must share the same SSA input, the logical shift must retain that input's width, both offsets must be constant, and the slice must reach the high end of a scalar no larger than eight bytes. The bit shift must equal eight times the nonzero byte offset. Arithmetic shifts, interior or truncated slices, mismatched inputs and unknown offsets are rejected. The existing circular-range intersection preserves signed, unsigned and wrapping value sets. No cached non-zero mask establishes the match.

Eight engine tests cover all 28 admitted high-byte slice shapes, rejection boundaries, exact signed/unsigned/wrapping range membership in both match directions, and the disabled gate. Six authored AMD64 functions cover 8-, 16- and 32-bit guards, signed bounds, a wide comparison and an explicit zero extension. Their complete C bodies agree with the original for 9,864 values across GCC/Clang at O0/O2 with UBSan. Complete Rust and Go bodies contribute another 9,864 comparisons. A combined check narrows four guards in the independently proven empty-match fixture; five unchanged Rust bodies compiled at O0/O2 preserve all 6,900 values, including empty/shared/default arms, enclosing loops and genuine loop exits. No emitted function body is repaired by a harness. CLI checks also compare omitted and explicit-off settings under all four presets.

Two comparisons each cover 43 images, 33,731 distinct functions and 75,909 language records. Every default function record is identical to its parent. Explicit enablement changes exactly 33 records: four authored functions and seven upstream functions in C, Rust and Go. Each gains one switch or match and loses one jump-as-call without adding a goto. All enabled function records exactly equal the previously reviewed enabled implementation. The 12 inherited Go parser failures remain unchanged. Complete enabled semantic review is retained under `enabled-study/`; the current comparison checks whole records against it.

Six independently captured Ghidra tables contain 246 entries. The replayable `static/verify-static-captures.py` checks their archived bytes and guard listings: entry zero retains the initialized zero, entries 1–40 set the corresponding index and reach the same continuation, and the out-of-range path sets 41. A formatter thunk's pointer slot binds it to the recovered target. That formatter now returns 32 rather than 64 bits; the independent listing shows its exits merge through `MOV EAX,EBX`. A decoder argument becomes signed 32-bit while retaining the same 32 argument bits, and recovered variables and cleanup branches follow the restored CFG. With the option enabled, the pinned angr single-block jump-table case at 0xbcf0 contains two switches instead of one. Supplied upstream executables were inspected statically and never run; unrelated upstream type, string and goto gaps remain outside these native claims.

Validation passes 675 original assertions, 3670 stage assertions and 10,299 workspace tests, with 39 ignored and no failures. The original baseline is unchanged. Tooling, lint, the live spec, catalog and shared counters also pass. Earlier successful validation is retained under `predependency/`; publication was held when the new empty Rust arm exposed the separately corrected emitter bug. The initial opt-in stage assertion also matched help text containing `jump-as-call`; its failed log is retained, and the assertion now matches the emitted call line.

Both predeclared speed studies use eight cases, 384 balanced paired rounds per case, disjoint physical CPU pairs and one final look. The enabled study failed: the upstream case added 10.772% median CPU and 11.210% median wall time, with upper bounds of 13.277% and 16.757%. The Rust control's wall bound also exceeded 5%. Every observation is retained under `enabled-study/`. The material follow-up adds the named default-off gate; it does not repeat the unchanged enabled implementation. The default-off study also fails its predeclared bound for scalar-c, narrow-guard, signed-guard. No passed speed study is claimed. The default-off maximum median CPU delta is 1.567% and wall delta 1.743%; simultaneous upper bounds reach 2.775% CPU and 10.674% wall. Binary, source and all 154 compiled specification hashes are verified before and after each study. These results apply to the recorded cases and binaries. Enabled recovery remains off regardless of the default-off timing outcome.
