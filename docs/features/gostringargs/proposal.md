# Validated Go string arguments

Recover a Go `string` parameter as one source value on amd64 ABIInternal when complete DWARF type and location evidence establishes its two-word input contract. Ship behind `gostringargs`, default off, requiring `godwarfsig`. This is one feature spanning source-contract recovery and emission; string results, slices, interfaces, stack arguments and other architectures remain separate work.

## Observed failure

The original five-function source has `Length(string) uint64`, byte-indexed sum/count loops, guarded first-byte access and a forwarding call. On both Go 1.22.5 and 1.27.3, the current complete emitted bundles fail to compile against those source signatures. `Length` takes two uint64 arguments; the loops take a pointer and length separately; `CallSum` loses its result after its callee contract is rejected. The native source produces matching results over empty, ASCII, NUL, invalid UTF-8 and multibyte inputs. Raw captures and compiler diagnostics are retained in the research record. No repaired-output result is claimed yet.

The pinned angr tests expect a `string` parameter for `main.count` and `main.parse` in `test_go_dwarf_signatures.py`. `test_go_decompiler.py` additionally expects string indexing and loop idioms. This proposal addresses the parameter contract and faithful access first; a byte loop cannot be replaced with UTF-8 range iteration merely to match a text assertion. Direct captures of all 21 expanded functions on both compiler versions confirm that pinned angr recovers the expected string signatures and forwarding calls. They also show ByteSum/ByteCount rewritten to range loops. A separately authored native construct witness demonstrates the difference: for é, numeric byte iteration sums 364 and counts the 0xa9 byte once, while range iteration sums 195 and counts it zero times. This is not a claim that the complete angr output compiles; those bodies remain unmodified in the captures.

## Contract recovery

Keep the current producer, architecture, source-origin and hidden-context checks. Identify strings using the Go kind and exact descriptor layout, not a name or any two-word struct. Both compiler versions expose kind 24, a 16-byte structure with `str: *uint8` at 0 and `len: int` at 8; raw DIEs and complete entry register pieces are retained. Validate a nonrecursive 16-byte value with byte pointer and signed machine-length fields at offsets zero and eight; reject conflicting metadata, malformed members, bitfields or inconsistent size/alignment. Attach the reserved canonical string type and validated GoString facet only after the full signature succeeds. Go strings hold arbitrary bytes; the facet documentation must not imply UTF-8 validity.

Extend bounded entry-location decoding to a complete pair of full-width register pieces. Match pointer then length against consecutive integer ABI slots. Scalar arguments keep their current validation and floating arguments use an independent register cursor. Reject exhaustion, stack storage, hidden contexts and conflicting or partial evidence rather than installing half a signature. Investigate the existing DWARF5 RET-only empty-range exception separately; any extension must retain the exact one-byte RET check. A missing piece is not an affirmative register location.

The current ABI model accepts scalar input slots of at most eight bytes, so ordinary struct assignment is insufficient. Validate an expanded scalar pointer/length signature against the model, then use existing `ParameterPieces::assign_address_from_pieces` and explicit input storage to describe one string argument. Revalidate grouped storage and all remaining parameters. Preserve existing scalar results, including the guarded two-integer-result option where applicable. Test caller reconstruction as well as entry declarations; a corrected signature with lost arguments is a failure.

## Emission

Enable string spelling only for the validated facet under the new option. Emit length projections with the recovered integer width (`int64(len(s))` on this target where required), preserving integer conversion semantics. Data projections must evaluate the original string value once and preserve its representation even when empty. `unsafe.StringData` leaves the empty result pointer unspecified, so an equivalent-layout header projection is the leading candidate. An authored construct test now preserves exact pointer/length bits and byte contents for ten representations on both compiler versions, including two non-null-backed empty strings. Projection evaluates its source once; reconstruction evaluates the pointer then length once each. Default, unoptimized and checkptr builds all pass. These are construct tests, not proof of future emitted bodies. Preserve any existing load, store and pointer offset semantics. Do not add UTF-8 stepping, bounds checks, reference creation or speculative loads.

Handle the actual partial-symbol and SUBPIECE forms produced by joined inputs. Known forwarding calls must pass a single recovered string and keep the scalar result. Any reconstruction from independent words needs an explicit proof and native test; do not silently substitute `unsafe.String`, whose checks could introduce panics. Named partial writes require an addressable equivalent-layout header view; a projection of a copied string would lose the write. An authored pointer-plus-int64 view preserves all 100 pairs of the ten tested representations and leaves the caller string unchanged on both compilers and all three build profiles. This remains construct evidence; emitted writes need their own proof. Keep C/Rust storage rendering faithful when the option is explicitly enabled, and keep all output languages unchanged when it is disabled.

## Validation

Compile and execute complete emitted functions without edits against the authored Go source on versions 1.22.5 and 1.27.3. An expanded 16-function source now covers string arguments before and after scalars, multiple strings, independent floating registers, forwarding calls and spills. It produces 1024 top-level function results per compiler plus the explicit Tick trace. The separate complete Pointer witness compares ten input header representations per compiler, including two non-null-backed empty strings. A separate four-body bundle adds StaticCaller and EffectOrder, retaining ByteSum and Mixed as complete callees. Both compiler sources pass 256 top-level results and 64 effect traces; trace 19 requires callback tag 1 before tag 2. Current parent bundles fail compilation. This brings the string/call witnesses to 18 distinct functions plus the separate Pointer witness. Include empty strings with distinct header representations, NUL, invalid UTF-8, multibyte input and numeric boundary values. Compare return values and effects, not just parser acceptance.

An authored 30-function cross-unit DWARF fixture is now built in compressed and plain forms; parent function records are identical across both forms and the scalar source-name control is recognized. Future option acceptance/refusal has not been tested. Add malformed-DWARF and metadata tests for wrong kinds, offsets, widths, partial or duplicate pieces, reversed registers, unsupported stack placement and ambiguous origins. Preserve existing scalar-only contracts and default-off captures. Add a two-pass end-to-end stage fixture and update catalog/corpus counts from actual captures. Describe contract and emission behavior in their owning spec chapters.

Run all four repository gates, tools/lint/catalog checks, and a full changed-function review over the existing pinned corpus. Classify every enabled-output change; no unresolved hunk is acceptable. Measure default-off against the frozen parent and on/off costs using a fixed randomized paired speed plan declared before samples. Retain raw outputs, native diagnostics, measurements and source/binary/spec hashes. No full Go parity claim follows from this bounded feature.
