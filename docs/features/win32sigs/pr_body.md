## The problem

kuna carries libc prototypes and not one Windows API signature, so on a PE every
`LoadLibraryExW` / `WriteFile` / `VirtualQuery` call has to have its arguments
guessed from the call site — and when that guess loses, the values are left
behind as stack locals.

```
$ kuna decompile ./win32sigs_pe_i386.exe 0x401020
void sub_401020(void)
{
  int v1; // edx
  wchar_t *v2; // stack - 0x10

  v2 = L"kernel32.dll";
  sub_401080(L"kernel32.dll",0,8);
  LoadLibraryExW((int)v2 + v1);
}
```

`LoadLibraryExW` takes three arguments. Two of them have been handed to the
unrelated `sub_401080` above it. On the reported binary the same shape costs 47
declarations where 8 would do, and the calls print `LoadLibraryExW()`,
`EnumResourceTypesW()` and `FreeLibrary()` with empty argument lists. The
fixture is generated by `win32sigs_pe_i386.py` beside it.

## The fix

- A built-in Win32 prototype table (`win32sigs`, default on), the Windows half of
  the `.gdt` stand-in `libproto` already is. ~130 `WINAPI` exports, ranked by an
  import histogram over 54 PE images rather than picked by hand, plus the
  resource/loader family the report was about.
- Parked by **entry address**, not by name. A PE import is two `FunctionSymbol`s —
  the size-0 IAT slot and the `FF 25` thunk a direct `call` targets — the global
  by-name query answers with the slot, and `ActionDefaultParams` asks about the
  thunk. `--assert 'prototype LoadLibraryExW …'` is byte-identical to no assert
  at all on the fixture; the same prototype at the thunk address repairs the
  call. A new `AnalysisOutput::prototypes_at` stream carries the address.
- Only callee-cleans exports, no CRT spellings: the x86 PE default model is
  `__stdcall` with an unknown `extrapop`, so a locked arity is also the callee's
  stack pop, and a `__cdecl` name here would get the wrong cleanup.
- A parameter with no width-stable spelling is rejected rather than
  approximated, which is why `SetFilePointerEx` and `RtlVirtualUnwind` are absent.

## The tests

`tests/cli/resource-loader-c-retains.json` runs the command above against the
vendored fixture and fails without the change. Unit tests pin the resource-family
arities, the CRT exclusion, and that the resolver names both the slot and the
thunk. Sweep over 22 PE images / 3,029 functions: 168 changed, 0 added, 0 removed,
and every changed function contains a call to a table name — 35 call sites gain
arguments to the documented arity, 16 shed invented ones
(`GetCurrentProcess(CONCAT44(dat_c,argc))` → `GetCurrentProcess()`). Parity is
675/675 and 704/704, and `sub_401ba0` decompiles 16.9% faster.

One kuna-owned stage assertion moved with the change. `ghdec-peimportcall` pinned
`ExitProcess(); // no-return`, an empty-parens spelling from before kuna had any
Win32 prototype. `ExitProcess` takes one `UINT`, and that fixture's
`bail(int code)` passes it, so `ExitProcess(a0)` is the correct rendering and the
old regex was pinning the argument being lost. What the test exists to protect,
the IAT-slot call binding to its import and keeping its no-return flow effect, is
unchanged; the other four assertions in the file are untouched.
