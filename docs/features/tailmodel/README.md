# `tailform model`: regenerating the weights

`model` is the default value of `tailform` (the 4-line size rule is `option tailform on`).

`decompiler/crates/kuna-decomp/src/p8_structure/kuna_tailform_weights.rs` is generated by `train.py` from two
runs of the decbench corpus with the function-tail decision forced each way. Each run sets
`KUNA_TAILFORM_DUMP`, which makes `kuna` append one JSON line per decided site (binary, function address, site,
features) to `<dir>/<pid>.jsonl`; no-return tails are not decision sites and are not dumped.

```sh
# 1. the two forced runs, with the dump (the decbench A/B harness: ab.py run <tag> <kuna> -- <kuna args>)
KUNA_TAILFORM_DUMP=$PWD/dump_wrap  python ab.py run tm_wrap  $KUNA -- --option tailform wrap
KUNA_TAILFORM_DUMP=$PWD/dump_guard python ab.py run tm_guard $KUNA -- --option tailform guard

# 2. label, evaluate held out by project, fit, write the table (numpy + scikit-learn)
python docs/features/tailmodel/train.py --harness <harness dir> \
    --dump-wrap dump_wrap --dump-guard dump_guard --tag-wrap tm_wrap --tag-guard tm_guard \
    --out-rs decompiler/crates/kuna-decomp/src/p8_structure/kuna_tailform_weights.rs

# 3. rebuild, then check the pinned decisions in kuna_tailform/tests.rs still hold
cargo test -p kuna-decomp --lib kuna_tailform
```

A site is a training example when both runs decided exactly one site in the function, the same one, the
function is not one `kuna_unoptimized` flags (there the 4-line threshold decides), and the function's control
flow matches the source under exactly one of the two forms; that form is the label. The script prints the
held-out comparison with the threshold (5 folds grouped by project, and the even/odd project-hash halves), the
learning curve on a quarter, half and three quarters of the examples, and the largest standardized weights.

## Replacing the shipped table

A new table ships only if it beats the current one on projects it was not fitted on. Write it twice more with
`--fit-only` and `--check-only`, run each end to end against the same baseline (`ab.py run <tag> <kuna> -- --option
tailform model` with that table built in), and add the CHECK gain of the first to the FIT gain of the second, per
optimisation level; do the same for the current table's training data. On main bd07ce279 a refit on 2,276 sites
gave 54 functions at O2 and 41 at O0 that way against 53 and 41 for the shipped table's data, and was 8 and 3
functions worse than the shipped table on the whole corpus, so the table fitted on main ff00f1108 stayed.
