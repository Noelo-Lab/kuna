## The residue, read

The one `OTHER` is `got-slot-named+cast-removed` that the classifier's regex
misses because the line carries a second `dat_` name that is not the slot:

```
-           __fprintf_chk((FILE *)*dat_2bf38,1,"\r%luk",dat_2ee10 >> 10);
+           __fprintf_chk(*stdout_ptr,1,"\r%luk",dat_2ee10 >> 10);
```

So the 45 changed lines are 38 slot namings (31 of which also drop a
`(FILE *)` cast the untyped slot needed), 5 declarations that take `FILE *` or
`FILE **`, one cast that APPEARS on a genuine `FILE *` global, and one return
type that becomes `FILE *`. Zero lines move a statement, an address or a
control-flow edge.

## The five declarations, and the two shadow hunks

tar `argp_parse` @0x3e690 -- a stack slot assigned `stdout` and nothing else:

```
-  unsigned long v70; // stack - 0x58            v70 = stdout;
+  FILE *v70;         // stack - 0x58
```

shadow `useradd` @0x18190 -- the local that carries `stdin` into `__fgets_chk`:

```
-  unsigned long v2;   v2 = *dat_21fb0;
+  FILE *v2;           v2 = *stdin_ptr;
```

`useradd` is the mixed image: `stdout` and `stderr` are copy-relocated AND have
a GOT slot pointing at the copy (defined, so it is not a stream fact -- the
relocation fill already renders it), while `stdin` is undefined and reaches the
program only through its GOT.

libselinux carries the other three, each `unsigned long *vN` -> `FILE **vN` on a
local holding `stdout_ptr`/`stdin_ptr`.

The two remaining hunks are shadow's `log_set_logfd`/`log_get_logfd` pair at
0x13350/0x13380, where the global `dat_246c8` is a real `FILE *` (it is assigned
`stderr` in the same function):

```
-    dat_246c8 = a0;              -  long sub_13380(void)
+    dat_246c8 = (FILE *)a0;      +  FILE * sub_13380(void)
```

The cast is honest: `a0` is a `long` parameter and the global is a stream.

## Controls that did NOT move

`fflush(stdout)`, `fputs_unlocked(s,stdout)`, `fwrite_unlocked(...,stdout)`,
`putc_unlocked`'s inlined `__overflow(stdout,c)` refill and every
`*(char **)&stdout->field_0x28` store are byte-identical in both arms across all
twelve binaries -- EIGHT of which are byte-identical end to end, every one an
executable: on those the type already arrived by inference from a typed stdio
call in the same function, which is exactly the reach this step extends. The four
that move are the two shared objects (whose streams reach the program only
through a GOT slot that had no name at all), plus `useradd`, which is the mixed
image, and `tar`, whose single changed line is a stack slot assigned the
copy-relocated `stdout` and nothing else.
