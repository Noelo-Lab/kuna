## hunt list
- **Signedness**: clean. Every `int4` loop index (`i<2` in RuleAndCommute/RuleAndPiece) and slot var is an explicit `int4`; `1-slot`/`1-i` mirror C++. `sa <= 0` (RuleDoubleArithShift, :1032) and `sa1+sa2 < 8*size` (:925) are signed comparisons matching C++. No `int4`-vs-`size()` comparison ported.
- **Integer widths**: clean (`uintb=u64`, `int4=i32`). `uintb->int4` truncations for shift amounts (`vn_offset(savn) as int4`) and `int4->uintb` for `new_constant` mirror C++ implicit conversions 1:1. Bare numeric `as` casts carry no `// cast:` comment (F2, MINOR).
- **Wrapping**: **clean (was F1, now repaired)**. All value-word shifts use `wshl`/`wshr` (`grep` confirms the only non-`w*` shift is the `>> 3`-by-constant at :1157). `wshl`/`wshr` = `wrapping_shl`/`wrapping_shr` (kuna-base/types.rs:127-129), masking count `& 63` for u64 — byte-for-byte identical to x86-64 SHL/SHR and to the C++ runtime that relies on it. The `(sa as u32)` round-trip (`int4 -> u32`, even for negative `sa` from `leastsigbit_set==-1`) reproduces C++'s `(int4)offset` + x86 `& 63` exactly. The handful of `int4 + int4` / `-diffsa` arithmetics (`sa1+sa2`, `offset1+offset2`, `8*size-sa`) are bare and would panic on pathological huge offsets — but they mirror C++ signed-overflow=UB, never overflow on realistic shift/SUBPIECE amounts, and are not in the wrap-prone value-word class (MINOR, carried from round 1).
- **Comparator totality**: clean. No `operator<`/comparator ported (`varnodes_equiv` is structural `Varnode::operator==`, not an ordering).
- **Iteration-order provenance**: clean. Only loops are fixed-index `0..2` (slot scan), identical to C++ `for(i=0;i<2;++i)`. No container iteration; no `HashMap`/`HashSet` (`grep` confirms).
- **Off-by-one / do-while / reverse iterators**: clean. The `while i<2 { ...; i+=1 }`+`break` ports of RuleAndCommute/RuleAndPiece preserve the C++ for-loop break-keeps-`i` / fallthrough-increments-`i` semantics; the post-loop `if i==2 {return 0}` fires exactly when C++'s does (re-read every continue/break/tail-`i+=1`, incl. the OR/PIECE inner-break vs fallthrough at :489-524). No `do{}while`, no reverse iterators.
- **Erase-while-iterating**: clean. No list/map erase during traversal (rules mutate via `op_set_input`/`op_set_opcode`/`new_op`+`op_insert_before`, never erase mid-iterate).
- **Exception->Result partial-state parity**: clean. C++ here has no `throw`; rules return `int4` (0/1). The `.expect(...)` panics only on internal-invariant violations (stale id / null def of a written vn), matching ADR-0004; on early-out (`return 0`) the rules read-then-decide before any mutation, so partial state is identical to C++.
