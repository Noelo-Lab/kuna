## Argument recovery is REAL (FOCUS 3) — proven on the live engine, not faked
Drove three call-heavy datatests through the live Rust engine (`KUNA_DUMP` on `decomp_test_dbg`, and the `XmlArchitecture`/`decompile_func`/`print_c` path in the adversarial tests) and compared the rendered call line to the C++ oracle direction:
- **noforloop_alias**: `might_change(RDI)` (1 arg) and `printf(RDI,RSI)` (2 args). C++ oracle: `might_change(i);` (1 arg) + `printf("Val = %d\n",...)` (>=2). The ARG COUNT differs per call (1 vs 2) and the order is System-V (RDI, RSI) — so this is per-call ProtoModel-driven recovery, NOT a "print all inputs" dump (the fspec in0 annotation is correctly excluded) nor a hardcoded count.
- **deindirect**: `(*Unique...)()` (opCallind deref-void form) AND `puts(RDI)` (opCall, 1 arg) coexist in the same body — opCallind and opCall both fire; the void (0-arg) CALLIND path is reached.
- **dupptr / loadstore_fieldarray**: `initstruct(RDI)` (1 arg) — a callee that is neither libc nor a literal, the recovery is fully general.

The recovery is gated on the real trial machinery: `Heritage::guard_calls` registers an input trial ONLY when `characterize_as_input_param(transAddr,size) == ContainsJustified` (the ProtoModel parameter-storage predicate) — so only ProtoModel-recognized register/stack slots become call args (heritage.cc:1496-1507, faithfully ported). `derive_input_map` -> `fillin_map` -> `fillin_map_standard` marks a trial `used` ONLY for a real ParamList slot (fspec.rs:2954), and `buildInputFromTrials` keeps only `isUsed()` trials in prototype-slot order. The chain (guardCalls -> checkInputTrialUse -> deriveInputMap -> buildInputFromTrials -> opCall) is end-to-end real.

NAME RESOLUTION caveat (LOSS-153c): the callee NAME resolves via `queryCall`->`read_loader_symbols` ONLY on the console `bootstrap_program` path (`decomp_test_dbg` datatest harness), where `might_change`/`printf`/`puts` resolve. The `XmlArchitecture::open_image` decompile path (used by the verifier's adversarial tests and the struct-corpus harness) does NOT install the loader symbol table, so direct calls there render the generic `sub_<addr>` fallback (`genericFunctionName(entryaddress)`). The *argument list is identical* on both paths; only the *name* is harness-dependent. The verifier confirmed both: names on the `decomp_test_dbg` path, arguments on the `XmlArchitecture` path.

## hunt list

- **Integer widths**: F1/LOSS-152 (callee_pop i64 vs int4, latent). Otherwise uintb->u64, int4->i32, sizes small; the `wrapOffset(stackoffset.wrapping_add(off))` and `off.wrapping_sub(spacebaseOffset)` match the C++ uintb wraps.

- **Comparator totality**: `sort_call_specs` is a stable `sort_by` on a tuple key whose second component (`getOrder()`) is unique per op — total, ties impossible; matches C++ unstable `std::sort` with `compareCallspecs`. No float compares.
- **Iteration-order provenance**: qlst is a `Vec` in push order then `sortCallSpecs`-ordered (dominance: block index then seqnum order) — matches C++ `vector<FuncCallSpecs*>`. Trial loops index `ParamActive` (insertion order). collectOutputTrialVarnodes walks `previousOp()` (intrusive op list). NO HashMap/HashSet in ported logic.
- **Off-by-one / do-while / reverse**: opCall comma counts (`count-1`) match C++; buildOutputFromTrials break-on-!isUsed matches; collectOutputTrialVarnodes `previousOp` walk breaks on non-INDIRECT exactly as C++.
